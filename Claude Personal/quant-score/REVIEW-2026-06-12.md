# Quant-Score Skill Audit — 2026-06-12

Reviewer: independent code + methodology audit. Scope: engine
(`scripts/quant_score.py`), tests, docs, deployed copy, and the six
sanity-check reports (MU, CRM, CEG, AVAV, RDW, SOFI).

## Verdict (bottom line)

This is a genuinely well-built deterministic scorer and a **trustworthy
*relative* ranking engine** — the code is clean, the structural-worst /
coverage-gap distinction is handled correctly, the WORST-peers-stay-in-pool
logic is right, and the six reports interpret the output honestly (every
one of them flags the methodology's blind spots in prose). It is fit for
its stated purpose: *"how does this stock rank against ~50 industry peers,
right now, on point-in-time fundamentals + trend."* It is **NOT** fit, and
must not be sold internally as, an absolute valuation or a cycle-aware
buy/sell engine: by construction it reads a cyclical at its earnings peak
(MU) as a Strong Buy, the composite-to-verdict thresholds are uncalibrated
hand-set numbers with no backtest, and the whole score swings on a noisy
~50-name yfinance peer set whose composition the user cannot see or audit.
The honesty of the surrounding docs is its saving grace — the engine's
weaknesses are disclosed, not hidden, so as *decision-support with the
caveats read* it is sound. As a number you would act on without reading the
David-Fit and Caveats sections, it is not. The "deterministic" claim is
true only within a snapshot day and the docs say so.

## What works (concrete strengths)

- **Clean separation of structural-worst vs coverage-gap.** `WORST`
  sentinel (line 48) ranks negative-earnings names at percentile 0 on the
  *affected ratio only*, while genuine missing data returns `None` and is
  dropped with weight redistributed (`score_pillar`, lines 161–175). This
  is the single most important design decision and it is implemented
  correctly. `value_metrics` (254–278) only pins to WORST when the
  denominator is structurally negative, and the post-loop sweep (275–277)
  catches negative lower-is-better ratios that yfinance reported as a raw
  negative number rather than omitting.
- **WORST peers stay in the ranking pool at the winsorize bound**
  (`score_ticker`, 648–659). A sector full of money-losers (RDW's
  aerospace set, SOFI's "credit services") therefore cannot make the target
  rank *artificially well* by having its bad peers silently dropped — they
  count at the worst end. The displayed `peer_median` uses real values only
  (668). This is subtle and correct, and it is directly tested
  (`test_score_ticker_counts_worst_peers_at_bound`).
- **Sign-aware estimate delta** (`estimate_delta`, 148–158) uses
  `abs(ago)` as denominator so a profit→loss forecast flip keeps a negative
  sign instead of inverting. Clamped to ±2. Tested for the zero-crossing
  case.
- **Determinism within a snapshot day is real**: batched single-request
  price download (`fetch_prices`, 481–496) gives an atomic same-bar
  momentum snapshot; per-ticker `.info`/EPS frames cached for the day;
  peer roster cached 7 days as the *full industry roster* (sym filtered on
  read) so every ticker in an industry sees a consistent peer set
  (`resolve_peers`, 543–591). Empty pools are never persisted, so transient
  network failures self-heal.
- **Midrank percentile with tie handling** (116–135) is textbook-correct,
  and the `lower_is_better` inversion is applied at rank time, not by
  negating values (avoids sign bugs).
- **NO-VERDICT discipline**: ≥2 N/A pillars → no composite, no invented
  verdict (`composite_score` 184–186, `decide_verdict` 196–199). The SKILL
  manifest reinforces "never invent one."
- **Reports are honest.** All six reports explicitly call out the
  methodology's limits (MU's cyclicality blindness, RDW's revisions-magnitude
  artifact, sector-relative momentum). The interpretation layer is doing the
  job the engine cannot.

## Bugs / correctness issues (severity-ranked)

### B1 — LOW: falsy-zero `or` chains can drop a legitimate exact-0 ratio
`value_metrics` (262–270) and `revisions` use `_num(x) or fallback`. Because
`_num(0.0)` returns the falsy `0.0`, a *legitimate* ratio of exactly 0.0
falls through to the fallback. Verified:
`value_metrics({'trailingEps':5,'trailingPE':0.0})['trailing_pe']` → `None`
(should arguably be 0.0 and ranked). Same pattern on `forwardPE`, `peg`,
`enterpriseToEbitda`. **Impact in practice: negligible** — a P/E or
EV/EBITDA of *exactly* 0.0 essentially never occurs in real data; PEG=0 is
likewise implausible. But it is a latent correctness smell and the right
fix is cheap: use an explicit `None`-check helper (`x if (n:=_num(x)) is not
None else fallback`) instead of `or`.

### B2 — LOW: `breadth` `g()` helper uses `_num(v) or 0` (line 349)
Same falsy-zero pattern. Here it is harmless: a true revision count of 0 and
a missing key both correctly contribute 0. No action needed; noted for
completeness.

### B3 — INFO (not a bug, but verify): `delta_fy0/fy1` have no winsorize
entry in CONFIG. They are *not* unguarded, though — `estimate_delta` already
clamps to ±2 before the value ever reaches `percentile_rank`. Verified that
RDW's headline "FY1 −200%" enters ranking as the clamp floor −2.0, and
because ranking is ordinal it simply lands at the bottom of the pool
alongside any genuine large cut. The near-zero-base artifact therefore does
**not** blow up the composite; it only affects the extreme tail. This is an
adequate guard, but it is implicit. Recommend a one-line comment in CONFIG
noting that `estimate_delta`'s clamp *is* the winsorization for these
metrics, so a future maintainer doesn't "fix" the missing bound by
double-clamping.

### B4 — INFO: `ensure_deps()` runs `pip install --break-system-packages`
at import (29–40). Fine for this user's setup, but it means importing the
module for *testing* can trigger a network/pip call on a fresh machine. The
tests happen to run because deps are present. Low risk; flag only because it
couples "import the scoring functions" to "mutate the environment."

No high- or medium-severity code bugs were found. The math (percentile,
grade bands, composite, verdict gating) is correct and matches the docs.

## Methodological weaknesses (severity-ranked)

### M1 — HIGH: structurally blind to cyclicality (the MU problem)
**Issue.** Every pillar is point-in-time and trend-following. At a cyclical
peak, peak earnings (cheap forward P/E), rising estimates (A-grade
revisions), and strong momentum all coincide — so the engine produces its
*highest* score exactly when forward risk is *highest*.
**Why it matters.** This is the dominant failure mode of a relative-momentum
+ forward-multiple system and it is not a small-print edge case; it is the
canonical way these scores lose money.
**Observed example.** MU: composite **4.24 Strong Buy**. Forward P/E 8.8
ranked **100th percentile** ("cheapest in the 43-name semi set") — but only
*because* consensus FY EPS exploded +68% (FY0) / +115% (FY1) over 90 days.
That is "cheap on peak earnings," and trailing P/E 46.5 ranked 81st (i.e.
expensive). FCF margin sat at 26th percentile despite a 41% net margin —
the supercycle-capex tell. The engine sees none of this as risk.
**Mitigation status.** Disclosed honestly in both `methodology.md` (Known
Limitations) and the MU report (a full "cyclicality is the dominant risk and
the score cannot see it" caveat). Disclosure is good; the *score itself*
still says Strong Buy.
**Recommended fix.** Add a non-scoring **cyclicality flag**, not a score
adjustment: when `forward_pe` ranks in the top decile *and* trailing P/E
ranks in the bottom half *and* FY revisions are top-decile, emit
`[!] Forward multiple built on sharply rising estimates — possible
peak-earnings / cyclical-top signature.` This keeps the engine deterministic
and objective while surfacing the trap mechanically rather than relying on
the LLM to remember to write the prose. A trailing-vs-forward-P/E divergence
metric is the cheapest single cyclicality proxy available from the existing
data.

### M2 — HIGH: the score is hostage to an unauditable ~50-name peer set
**Issue.** yfinance industry classification drives everything, and it
produces odd cohorts: V/MA in "credit services" with SOFI; NVDA inside MU's
semiconductor set; a software set mixing DUOL/SHOP with CRM. Peer
composition can swing a pillar grade by multiple letter grades, and the
user never sees the full roster (output truncates at 12 names, line 738).
**Why it matters.** A "B- Profitability" vs profitable defense primes
(RDW's set includes RTX/LMT/NOC/GE) is a *much* harder bar than vs a
space-SPAC cohort — the report even says so. The grade is only as meaningful
as the cohort, and the cohort is a yfinance artifact.
**Observed example.** SOFI Profitability F is partly "credit services"
containing V/MA (best-in-class profitability) as peers; NVDA being *inside*
MU's peer pool is why MU's momentum is only B despite +751% (the methodology
log frames this as intended sector-relative behavior, and for momentum it
is — but the same cohort drives Value/Profitability where it is less
obviously "intended").
**Mitigation status.** widen_below tuned 10→8 to stop cross-industry
pollution (good, logged). max-50/min-8 is reasonable. But the core
dependency on yfinance taxonomy is unaddressed and partly unaddressable.
**Recommended fix.** (a) Print the *full* peer roster (or count by sub-flag)
in `--json` and ideally in text, so the cohort is auditable. (b) Add a
"peer-set composition" caveat to every report that names the 3–4 largest
peers by cap so the reader can sanity-check the cohort. (c) Consider a
diagnostic that flags when the peer set's median market cap is >10x or <0.1x
the target's (mega-cap-prime contamination of a small-cap target, as in
RDW).

### M3 — MEDIUM: forward-P/E rewards "cheap on peak earnings" with no guard
**Issue.** Value pillar treats a low forward P/E as unambiguously good, but
forward P/E is `price / consensus-forward-EPS`, and a low value can mean
either "genuinely cheap" or "consensus is extrapolating an unsustainable
earnings spike." The engine cannot tell them apart.
**Why it matters.** This is the *mechanism* behind M1; calling it out
separately because the fix is local to the Value pillar.
**Observed example.** MU forward P/E 8.8 → 100th percentile Value input.
**Recommended fix.** Either (a) down-weight forward P/E relative to trailing
P/E and EV/EBITDA inside the Value pillar, or (b) compute a PEG-style sanity
check and flag when forward P/E is "cheap" *only* because of a >50% 90-day
EPS-estimate jump. Do not silently penalize — flag. (Ties into M1's flag.)

### M4 — MEDIUM: equal pillar weights + hand-set thresholds, zero backtest
**Issue.** `pillar_weights = (1,1,1,1,1)` and verdict cuts
(SB 4.0 / Buy 3.5 / Hold 2.5 / Sell 1.5) are admittedly un-backtested
(calibration log: "initial; no backtest data"). The 4.0 SB threshold was set
by "spec amendment (4.5 unattainable)" and validated only against a
sanity *basket of 8*, not predictive performance.
**Why it matters.** The composite-to-verdict map is the entire decision
output, and it is currently a reasonable-looking guess. Equal weighting in
particular has no theoretical or empirical backing — Alpha Picks itself
does not weight equally, and momentum vs value vs revisions have very
different forward-return profiles. The bands are also asymmetric: a stock at
the *exact median* of every pillar (50th pctl) maps to composite 3.0 = Hold,
Hold spans 2.5–3.5 (37.5–62.5 pctl, a very wide net), Buy is a narrow
3.5–4.0 (62.5–75 pctl), and Strong Sell (<1.5) requires sub-12.5th-pctl
composite — nearly unreachable. So the system is structurally reluctant to
say "Strong Sell" and easy to land in "Hold."
**Mitigation status.** Honestly logged as un-backtested. Selectivity was
*spot-checked* (only 1 Strong Buy in a 7-name basket), which is weak
evidence the thresholds aren't trivially loose, but says nothing about
predictive value.
**Recommended fix.** Treat the composite as an *ordinal* signal, not a
calibrated probability — the docs/report language should avoid implying the
4.0 cut means anything more than "top of this basket." Longer term: a
minimal forward-return backtest (even 1–2y, even crude) to justify weights
and cuts, or explicitly re-label the verdict as "relative rank tier" rather
than Buy/Sell. At minimum, document that "Hold" is the wide default band so
readers don't over-read a 3.2 Hold as a considered neutral call.

### M5 — MEDIUM: revisions magnitudes on near-zero EPS bases (mostly mitigated)
**Issue.** Percent estimate changes on a loss-making company with EPS near
zero produce nonsense magnitudes (RDW "FY1 −200%").
**Why it matters.** If the raw percent leaked into the score it would be
garbage.
**Observed example.** RDW report: FY0 −78.9% / FY1 −200%.
**Mitigation status — GOOD.** `estimate_delta` clamps to ±2 *before*
ranking, and ranking is ordinal, so the artifact lands at the bottom of the
pool next to any genuine large cut without distorting the composite (B3
above). The report correctly leans on **breadth (−1.0, every revision a
cut)** as the reliable signal and explicitly distrusts the magnitude.
**Recommended fix.** Minor: in the report-facing evidence, suppress or
asterisk the raw percent for loss-making names and lead with breadth.
Engine-side this is already adequate; just document the clamp-as-guard
(B3).

### M6 — LOW/MEDIUM: structural-worst pinning vs dropping
**Issue.** Negative-earnings names get pinned to percentile 0 on the
affected ratio rather than dropped. In a sector that is *mostly*
money-losers (RDW's space cohort, biotech, etc.), many names share the WORST
floor.
**Assessment — this is the right call.** Dropping them would let a
pre-profit name's Value pillar quietly vanish and inflate the composite via
reweighting; pinning to WORST correctly says "no earnings = worst value,"
and the WORST-peers-in-pool logic (M-strength above) prevents the
*reverse* distortion. The ties-share-a-percentile midrank handling means a
field of money-losers all sitting at WORST don't individually drag the
target below where it belongs. Confirmed correct in `score_ticker`. No
change needed; calling it out because the prompt asked and because it *looks*
risky but is actually sound.

### M7 — LOW: "deterministic" is an overclaim if read literally
**Issue.** Headline docstring says "Deterministic: same-day re-runs hit a
snapshot cache and return identical results." True *within a day*. But
`.info` values drift intraday on *first* run at different times (MU logged
4.26, ran 4.24), so two cold runs hours apart differ.
**Mitigation status.** Disclosed in Known Limitations and the snapshot date
is stamped. The claim is technically accurate (it says *same-day re-runs*,
i.e. cache hits).
**Recommended fix.** Tighten the headline to "deterministic per snapshot
(cache); first-run values can drift intraday with the data source" so the
word isn't doing more work than it should.

### M8 — LOW: look-ahead / survivorship
**Issue.** Peers come from *current* yfinance industry top-companies →
survivorship-biased cohort (dead/delisted peers absent), and all fundamentals
are latest-available TTM/forward consensus. No point-in-time reconstruction.
**Assessment.** For a *current-snapshot ranking* tool (not a backtester)
this is acceptable and largely unavoidable with yfinance. It would only bite
if someone tried to backtest the score using this code as-is — which would
silently use today's roster for a past date. Worth a one-line warning in
methodology that the tool is not backtest-safe.

## Test-suite assessment

**Pass result:** `45 passed in 1.10s` (ran `python -m pytest quant-score/tests`
from `D:\AI Stuff\Claude Personal\`).

**What's well covered (genuinely, not superficially):**
- The risky scoring primitives: percentile midrank, ties, WORST sentinel,
  thin-pool→None, lower-is-better inversion.
- Grade-band boundaries tested at the exact cutoffs (96.9→A, 44.9→D+, etc.).
- `estimate_delta` zero-crossing sign and ±2 clamp — the subtle part.
- Composite renormalization for 1 N/A and NO-VERDICT for 2 N/A.
- Verdict gating: Strong-Buy pillar-floor demotion AND value circuit
  breaker, both with the right notes.
- Structural-worst extraction (P/E, PEG, EV/EBITDA) and the negative-ratio
  sweep.
- `test_score_ticker_counts_worst_peers_at_bound` — the single most
  important integration test, and it correctly asserts both the rank (50.0,
  middle of [20,30,150]) and the evidence median (real values only, 20.0).
  This is the highest-value test in the suite.

**Coverage gaps / false confidence:**
1. **No test exercises `run()` or `resolve_peers()` end-to-end** (both hit
   the network, so understandable) — meaning the *peer-set construction,
   widening rules, universe filtering, and name-dedupe at the candidate
   level* (the M2 risk surface, and arguably the most consequential logic in
   the whole system) are **untested**. `_norm_name` is tested in isolation
   but `_filter_universe`'s EQUITY gate / cap / price / dedupe interaction
   is not. A fixture-injected test of `_filter_universe` with mocked
   `fetch_info` would close this cheaply and is worth doing.
2. **No test for the widen-below cascade** (industry → sibling industries →
   sector). The 10→8 calibration that the log says fixed peer pollution has
   no regression test, so a future change could silently reintroduce it.
3. **`composite_score` band-edge values are tested, but the verdict
   *thresholds* are only tested at safe interior points** (4.2, 3.6, 3.0).
   No test pins behavior exactly at 3.5 or 2.5 (boundary `>=` semantics).
   CRM landed 3.46 — 0.04 under the Buy line — so boundary behavior is
   real-world relevant; an off-by-epsilon change to a `>=` would not be
   caught.
4. **No test that the sector mask is actually applied inside the full
   scoring path** beyond `build_all_metrics` (it is tested there — good —
   but not that masked metrics are excluded from the pillar score
   correctly).
5. **Determinism is asserted nowhere** — no test that two scores of the same
   fixture inputs are bit-identical (would be trivial and would lock in the
   pure-function contract of `score_ticker`).

**Net:** the tests are *not* superficial — they target the genuinely tricky
math and the WORST-peer logic well. But they give **false confidence about
peer-set construction**, which is the part most likely to silently corrupt a
real score (M2). The unit core is solid; the data-assembly layer is a
blind spot.

## David-Fit overlay assessment

**Clean separation — good.** `david-fit.md` is explicit that the overlay is
applied *by Claude after* the objective score and **never changes grades or
the verdict** ("a separate David Fit section"). The engine has zero
knowledge of David's preferences — no personalization leaks into CONFIG or
the scoring path. This is the correct architecture: objective score stays
reproducible and shareable, subjective fit stays a labeled overlay. The MU
and RDW reports honor it (the engine's Strong Buy on MU is preserved while
the overlay adds the cyclicality/horizon caveat as commentary, not a score
change).

**Minor risk:** the overlay's power lives entirely in the LLM following the
markdown each run — e.g. the "trailing P/E > 100 → HARD PASS" rule is not
enforced anywhere in code, so a run where the model forgets to read
`david-fit.md` would silently drop it. For a hard rule like P/E>100, consider
having the *engine* emit a `[!]` flag (it already has trailing P/E), so the
hard pass is mechanical and the overlay just interprets it. The market-cap
<$1B flag has the same property. This would make the two *hard* flags
robust to LLM forgetfulness while leaving the soft "fit signals" as
prose-only.

## Prioritized recommendations (highest leverage first)

1. **Add a mechanical cyclicality / peak-earnings flag** (M1, M3): when
   forward P/E is top-decile while trailing P/E is bottom-half and FY
   revisions are top-decile, emit a `[!]` flag. This converts the single
   biggest blind spot from "hope the LLM writes the caveat" to a
   deterministic engine output. Highest leverage by far — it directly
   addresses the MU-type false-Strong-Buy.
2. **Make the peer set auditable** (M2): print the full roster in `--json`,
   name the largest peers in every report, and flag extreme cap mismatch
   between target and cohort median. The grade is only as good as the
   cohort and right now the cohort is invisible.
3. **Test the data-assembly layer** (test gap 1–2): fixture-mocked tests for
   `_filter_universe` and the widen-below cascade. This is the untested,
   most-consequential, hardest-to-eyeball logic.
4. **Re-label the composite as an ordinal rank tier, not a calibrated
   score** (M4), and document the wide "Hold" band — until/unless a real
   backtest justifies the weights and the 4.0/3.5/2.5 cuts.
5. **Promote the two David hard flags into engine `[!]` flags** (overlay
   robustness): trailing P/E>100 and cap<$1B are mechanical; don't leave
   them to LLM recall.
6. **Tighten the "deterministic" wording** (M7) and add a "not backtest-safe
   / current roster only" note (M8). Cheap honesty.
7. **Fix the falsy-zero `or` chains** (B1) and add the boundary verdict
   tests at exactly 3.5/2.5 (test gap 3). Low impact but cheap and removes
   latent traps.

### One-line summary
A well-engineered, honestly-documented *relative* ranking tool whose code is
correct and whose tests cover the math well — but whose verdict is
structurally blind to cyclicality, hostage to an invisible yfinance peer
set, and gated by un-backtested thresholds. Trust it to rank a stock against
its cohort; do not trust the Strong Buy/Sell label without reading the
caveats. No source-vs-deployed drift; no high-severity code bugs.
